# ターミナル・シェル・エディタの基礎知識

「ターミナル」「シェル」「コンソール」「エディタ」……似たような言葉がたくさん出てきて混乱しますよね。この章では、これらの概念の違いを整理し、この Book の dotfiles で何を使っているかを紹介します。

## ターミナル・シェル・コンソールの違い

### 混乱しやすい理由

これらの用語が混乱しやすいのは、歴史的な経緯でほぼ同じ意味で使われることが多いためです。しかし、厳密には異なる概念を指しています。

Microsoft の Scott Hanselman 氏はブログ記事[^1]で「**シェルの選択がターミナルアプリケーションの選択を決めるべきではないし、その逆も然り**」と述べています。つまり、これらは独立した存在です。

### 3 つの関係

```
┌─────────────────────────────────────────────────────┐
│              ターミナル（エミュレータ）                  │
│                                                     │
│   テキストの入出力を表示する「画面」                    │
│   フォント・色・透過度・ウィンドウサイズを管理            │
│                                                     │
│  ┌───────────────────────────────────────────────┐  │
│  │                 シェル                          │  │
│  │                                               │  │
│  │   コマンドを解釈・実行する「頭脳」                │  │
│  │   補完・履歴・変数・パイプを処理                  │  │
│  │                                               │  │
│  │  $ ls -la          ← コマンドを入力            │  │
│  │  $ vim config.yml  ← エディタを起動            │  │
│  │  $ python app.py   ← プログラムを実行          │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

MIT の「The Missing Semester of Your CS Education」[^2]では、シェルを次のように説明しています。

> 現在のコンピュータには GUI、音声、AR/VR などさまざまなインターフェースがある。これらは 80% のユースケースには便利だが、できることに根本的な制限がある。コンピュータが提供するツールをフルに活用するために、テキストベースのインターフェース、すなわち「シェル」を使う必要がある。

ターミナルとシェルの関係は、**ブラウザと Web アプリの関係**に似ています[^4]。Chrome や Firefox（ブラウザ = ターミナル）を変えても、中で動く Gmail や YouTube（Web アプリ = シェル）は同じように使えます。逆に、同じブラウザで別の Web アプリを開けるように、同じターミナルで bash や zsh を切り替えられます。

シェルの名前の由来は、OS の中核である「カーネル（核）」を包む「殻（シェル）」です[^3]。ユーザーの命令をカーネルが理解できる形に翻訳して伝える仲介役と考えると分かりやすいでしょう。

```
ユーザー  ─→  シェル（殻）  ─→  カーネル（核）
  命令       コマンドを解釈       OS の中核処理
            変数・補完・履歴      プロセス管理
            パイプ・リダイレクト   ファイルシステム
```

### 用語の整理

| 用語 | 意味 | 具体例 |
|------|------|-------|
| **コンソール** | もともとは物理的な入出力装置（キーボード + モニター） | 昔のメインフレームの操作卓 |
| **ターミナル** | コンソールをソフトウェアで再現したもの（＝ターミナルエミュレータ） | Windows Terminal, iTerm2 |
| **シェル** | コマンドを解釈・実行するプログラム | bash, zsh, fish |

:::message
現代では「コンソール」と「ターミナル」はほぼ同じ意味で使われます[^1]。この Book では「ターミナル」で統一します。
:::

## ターミナルエミュレータ

ターミナルエミュレータは「画面」の役割です。好みで選んで問題ありませんが、GPU アクセラレーション対応のものは大量のログ出力時にカクつきにくいです。

### エディタの統合ターミナル vs 専用ターミナル

最近のエディタ（Zed, VS Code 等）には**統合ターミナル**（integrated terminal）が内蔵されています。1つのプロジェクトに集中して作業する分にはこれで十分です。

ただし、**複数のプロジェクトを行き来したい場合**や、**エディタとは独立したターミナルセッションが欲しい場合**は、専用のターミナルエミュレータを使う方が快適です。タブやペイン分割でプロジェクトを整理したり、ターミナルマルチプレクサ（Zellij, tmux）と組み合わせてセッションを維持したりできます。

筆者のおすすめは [Tabby](https://tabby.sh/) です。クロスプラットフォーム対応で、SSH 接続管理やシリアルポート対応など、リモート作業に便利な機能が組み込まれています。プラグインでの拡張性も高く、統合ターミナルでは物足りなくなったときの次のステップとして良い選択肢です。

### ターミナルエミュレータの比較

| ターミナル | OS | GPU | 特徴 |
|-----------|-----|-----|------|
| [Tabby](https://tabby.sh/) | 全 OS | ✅ | SSH 管理内蔵、プラグイン拡張、クロスプラットフォーム |
| [Windows Terminal](https://github.com/microsoft/terminal) | Win | ✅ | Windows 標準、WSL 連携が優秀 |
| [iTerm2](https://iterm2.com/) | Mac | ❌ | macOS の定番、機能が豊富 |
| [WezTerm](https://wezfurlong.org/wezterm/) | 全 OS | ✅ | Lua で設定、クロスプラットフォーム |
| [Ghostty](https://ghostty.org/) | Mac/Linux | ✅ | Zig 製、ネイティブ UI で高速 |
| [Alacritty](https://alacritty.org/) | 全 OS | ✅ | 最速、ただしタブ・分割なし |
| [kitty](https://sw.kovidgoyal.net/kitty/) | Mac/Linux | ✅ | 画像表示対応、拡張性が高い |

各ターミナルの詳細な比較は以下の記事が参考になります:

- [Ghostty 公式: Terminal Emulator Comparison](https://ghostty.org/docs/help/comparison)
- [WezTerm 公式: What is a Terminal Emulator?](https://wezfurlong.org/wezterm/what-is-a-terminal.html)

## シェル

### なぜ zsh を選んだのか

この dotfiles では **zsh** を採用しています。理由はシンプルです:

- **bash とほぼ互換** — bash のスクリプトや知識がそのまま活きる
- **macOS のデフォルト** — Catalina 以降の標準シェル
- **プラグインエコシステムが豊富** — sheldon + zsh-defer で起動も高速に保てる
- **強力な補完** — あいまい補完（`/u/l/b` → `/usr/local/bin`）や再帰グロブ（`**/*.md`）

```
$ cd /u/l/b[TAB]      # → /usr/local/bin（あいまい補完）
$ ls **/*.md           # 再帰グロブ（bash では shopt が必要）
```

### 他のシェルとの位置づけ

| シェル | 一言で言うと | POSIX 互換 |
|-------|-----------|-----------|
| **bash** | どこにでもある標準。スクリプトの共通言語 | ✅ |
| **zsh** | bash 上位互換 + 強力な補完とプラグイン ← **この dotfiles** | ✅ |
| [fish](https://fishshell.com/) | 設定なしで便利、ただし独自構文 | ❌ |
| [nushell](https://www.nushell.sh/) | データ指向の次世代シェル | ❌ |

:::message
どのシェルを選んでも、**bash の基本構文は覚えておくべき**です。CI/CD、Docker、サーバー管理ではほぼ bash が前提です。日常の対話シェルは好きなものを、スクリプトは bash で書く、という使い分けが現実的です。
:::

各シェルの詳細な比較は以下が参考になります:

- [MIT: The Missing Semester — The Shell](https://missing.csail.mit.edu/2020/course-shell/)（[日本語訳](https://missing-semester-jp.github.io/2020/course-shell/)）
- [fish shell 公式: Design](https://fishshell.com/docs/current/design.html) — fish が POSIX 非互換を選んだ理由
- [Nushell 公式: Thinking in Nu](https://www.nushell.sh/book/thinking_in_nu.html) — 従来のシェルとの違い

## エディタ

### CUI エディタと GUI エディタ

エディタは大きく 2 種類に分けられます。

```
CUI エディタ                         GUI エディタ
┌─────────────────────┐            ┌─────────────────────┐
│ $ vim config.yml    │            │ ┌─ Zed ──────────┐  │
│                     │            │ │ ファイルツリー │本文│ │
│ server:             │            │ │               │   │ │
│   port: 8080█       │            │ │               │   │ │
│   host: 0.0.0.0     │            │ │ ──────────────│   │ │
│ ~                   │            │ │ ターミナル     │   │ │
│ -- INSERT --        │            │ └───────────────────┘ │
└─────────────────────┘            └─────────────────────┘
ターミナルの中で動く                  独立したウィンドウで動く
SSH 先でもそのまま使える              マウスで直感的に操作
```

### この dotfiles のエディタ構成

| 用途 | エディタ | 理由 |
|------|---------|------|
| メイン開発 | **Zed** | Rust 製で高速、AI 統合、VS Code ライクな操作感 |
| サーバーでのちょっとした編集 | **vim** | SSH 先でもすぐ使える、どこにでもある |

Zed の設定やキーバインドについては [Zed エディタ](./13-zed-editor) チャプターで詳しく解説しています。

### 他のエディタとの位置づけ

| エディタ | 種類 | 一言で言うと |
|---------|------|------------|
| [VS Code](https://code.visualstudio.com/) | GUI | 拡張機能の王。情報量・コミュニティが最大 |
| **[Zed](https://zed.dev/)** | GUI | 高速 + AI 統合。VS Code からの移行が楽 ← **この dotfiles** |
| [Cursor](https://www.cursor.com/) | GUI | AI ファーストなエディタ |
| **vim** | CUI | SSH 先で必須。モーダル編集 ← **この dotfiles（サブ）** |
| [Neovim](https://neovim.io/) | CUI | vim のモダン版。Lua で設定、LSP 統合 |
| [Helix](https://helix-editor.com/) | CUI | Rust 製のモダン CUI エディタ |

エディタの選択は好みや開発スタイルによるところが大きいです。以下のリソースが選択の参考になります:

## ターミナルマルチプレクサ

ターミナルマルチプレクサは、**1 つのターミナルで複数のセッションを管理**するツールです。代表的なものに [tmux](https://github.com/tmux/tmux) や [Zellij](https://zellij.dev/) があります。

```
マルチプレクサ使用時
┌──────────────────────┐
│ ペイン1  │ ペイン2    │
│ vim     │ サーバー   │
│         │ ログ      │
│─────────┼──────────│
│ ペイン3               │
│ $ git status          │
├──────────────────────┤
│ [0] main  [1] server │ ← ウィンドウ（タブ）切替
└──────────────────────┘
```

「エディタの統合ターミナルがあるのに必要？」と思うかもしれません。統合ターミナルはエディタと一体で便利ですが、**複数プロジェクトのセッションをまたいで管理したい場合**や、**SSH 接続が切れてもサーバー上のプロセスを維持したい場合**にはマルチプレクサが活躍します。

この dotfiles では **Zellij** をターミナルマルチプレクサとして使っています。画面上にショートカットキーが常に表示されるため、暗記不要で直感的に操作できます。

詳しくは [Zellij でターミナルマルチプレクサ入門](./14-zellij) チャプターで解説しています。

## まとめ

```
┌──────────────┬──────────────────────────────────────┐
│ レイヤー      │ この dotfiles の構成                   │
├──────────────┼──────────────────────────────────────┤
│ ターミナル    │ 好みのものを自由に                     │
│ シェル        │ zsh + sheldon + starship              │
│ エディタ      │ Zed（メイン）/ vim（サーバー用）        │
│ マルチプレクサ │ Zellij                                │
│ ランタイム管理 │ mise                                 │
│ CLI ツール    │ eza, fzf, fd, bat 等                  │
└──────────────┴──────────────────────────────────────┘
```

それぞれが独立したレイヤーなので、**一度に全部を決める必要はありません**。まずはデフォルトのターミナルと bash / zsh で始めて、不便を感じたら一つずつ入れ替えていく、というアプローチがおすすめです。
